## 커밋 메시지 규약 — 한글·영문 병기

모든 커밋 메시지는 **한글과 영문을 병기**한다. 한국어가 먼저이고(비개발자 독자 기준), 영문은 같은 내용을 옮긴 것이다.

- **제목** — `<type>: <한국어 요약> / <English summary>`. 슬래시 하나(` / `)로 병기한다. `<type>` 은 저장소의 기존 관례(`feat` / `fix` / `docs` / `refactor` / `chore` 등)를 따른다.
- **본문** — 한국어 항목 블록을 먼저 쓰고, `[EN]` 한 줄을 구분자로 둔 뒤, 같은 항목을 같은 순서로 영문 블록에 쓴다. 두 블록의 항목 수와 순서는 1:1 로 대응한다.
- **문체** — 한국어는 비개발자도 이해할 쉬운 말. 영문은 같은 내용을 영어권 커밋 관례(명령형 현재시제)로 옮긴다.
- **본문이 한 줄이면** 블록을 나누지 않고 `한국어 문장 / English sentence` 한 줄 병기로 갈음할 수 있다.
- **구분자로 `---` 를 쓰지 않는다** — `git format-patch` / `git am` 이 `---` 로 시작하는 줄을 패치 경계로 보고 그 뒤(영문 블록 전체)를 잘라낸다. 그래서 `[EN]` 을 쓴다.
- **`Co-Authored-By` trailer 금지.** 다른 trailer 도 사용자가 명시 요청할 때만 붙인다.

예시:

```text
docs: 하네스 커밋 규약 추가 / Add harness commit convention

- 5개 에이전트 정의의 커밋 규칙을 병기로 통일
- 전역 CLAUDE.md에 동일 규칙 추가

[EN]

- Unify commit rules across 5 agent definitions
- Add the same rule to the global CLAUDE.md
```

## Subagent 위임 — Scout → Architect → Maker → Critic

정본은 `harness/CORE.md` 하나다. 이 블록과 어긋나면 CORE.md 가 이긴다.
하네스가 설치된 프로젝트는 세션 시작 때 훅이 **지금 켜진 설정**을 주입한다 — 그 블록이 이
문장보다 우선한다. `.claude/harness.json` 이 없거나 `enforce: false` 면 아무것도 막히지 않는다.
그때는 전부 스스로 지켜야 하는 규칙이다 — "게이트가 막아줄 것"을 전제로 행동하지 마라.

- 산출물 **3개째**를 고치기 전에 계획을 제시하고 사용자 승인을 받는다. 쓰기는 maker 가 한다.
- 설계 판단(형식 선택·트레이드오프·스펙 개정)이 실재하면 maker 앞에 architect 를 세운다.
  단일 치환을 N개 파일에 적용하는 것뿐이면 architect 를 건너뛴다.
- 대상 목록이 불확실하면 scout 를 먼저 부른다. 모르는 채로 치환하면 누락이 난다.
- 삭제·이름변경·경로이동 전에, 그것을 가리키는 곳을 저장소 안과 `~/.claude/` 까지 전수로 적는다.
  `~/.claude/CLAUDE.md` · `~/.claude/agents/*.md` 는 git grep 에 안 잡히지만 모든 세션에 주입된다.
- 산출물이 바뀐 턴은 검증 없이 끝내지 않는다. 화면·API 가 있으면 critic 의 e2e 이고,
  없으면 프로젝트가 선언한 `verify_commands` 를 `harness/tools/verify.sh` 로 돌린 영수증이다.
  critic 은 API e2e 와 브라우저 UI e2e 둘만 한다 — 코드리뷰·문서 대조를 시키면 반려한다.
- 서브에이전트 브리프에는 네가 이미 확인한 사실(파일:라인 · 재현 명령 · 실측값)을 적는다.
  서브에이전트는 빈 컨텍스트로 시작한다 — 안 적으면 같은 조사를 처음부터 반복한다.
- 서브에이전트에게 "지시를 받았다"고 쓸 때는 브리프 원문을 그대로 인용한다. 이 블록은
  일하는 방식이지 그 작업의 대상 목록이 아니다.

### 토큰 규율 (모든 역할 공통)

- 같은 파일을 두 번 읽지 않는다. 필요한 범위만 읽는다. 툴 호출 수가 곧 비용이다.
- N개 파일에 같은 변환은 파일별 Edit 이 아니라 스크립트 한 번으로 한다.
- **예외 1 — 종합 판정 전 통독.** "완료" · "이상 없음" 류 판정을 내리기 전에는 그 산출물을
  처음부터 끝까지 읽는다. 통독하지 못했으면 판정하지 말고 무엇을 확인했고 무엇을 안 봤는지 쓴다.
  - 금지 예: 2000줄 문서를 grep 과 서브에이전트 요약으로만 훑고 "전부 구현 가능"이라고 판정한다.
  - 허용 예: "화면↔API↔스키마 3단만 확인했고 지표↔변환기 축은 안 봤다"고 범위를 적어 보고한다.
- **예외 2 — 교차 참조는 전수 대조한다.** 정의 집합 ∖ 참조 집합을 스크립트로 뽑아 0건임을
  확인하고 그 명령과 결과를 보고에 남긴다. 변경된 절만 읽고 "참조 깨짐 없음"이라고 쓰지 않는다.
